# OCR 文字擷取

提供文字選取的 OCR 備援與手動區域 OCR；辨識結果只複製到剪貼簿，不變更 PDF。

## 操作

工具列提供互斥的「複製文字」與「區域 OCR」兩種模式，一般預覽與全螢幕皆可使用。

「複製文字」沿用 PDF 文字層選取，拖曳選取並放開滑鼠。

- 正常文字直接複製，拖曳時只更新高亮。
- 若放開滑鼠取得的文字含 U+FFFD（�）、Unicode 非字元、孤立代理碼或非換行／Tab 的控制字元，才啟動 OCR。
- 在「複製文字」模式中，空白或純圖片選取不觸發 OCR。
- OCR 在現有背景程序中執行，將所選字形按行以 400 DPI 渲染；成功後複製辨識結果，狀態列提示校對。
- 採用 RapidOCR 3.10.0 與 CPU 版 ONNX Runtime，直接在 Python 中辨識，不呼叫 Tesseract 或其他外部執行檔，也不寫入暫存辨識影像。
- 第一次需要 OCR 時才載入模型，後續重用同一個引擎。一般文字備援僅載入辨識模型；「區域 OCR」首次使用時另載入偵測模型，兩者共用辨識引擎。不載入方向分類模型。
- 模型或函式庫遺失、初始化失敗、結果為空／損壞，或平均字元信心低於 0.8 時，保留原始文字並顯示原因。
- 每次最多 30 行、每行影像上限 2,000 萬像素。各行間檢查 60 秒總預算；原生推論進行中無法硬性中斷。

「區域 OCR」使用十字游標，拖曳矩形範圍後才辨識，支援掃描圖片、截圖及一般 PDF。拖曳期間不進行背景 OCR；空白範圍不覆寫剪貼簿。偵測文字行後，將同一行的短橫線、底線等標記合併辨識。大片區域會適度降低解析度，避免超過約 1,900 萬像素。

自動備援的判斷採保守策略，無法偵測所有錯字：若損壞映射剛好產生合法中文字，或原文使用私用區字元，仍沿用原始文字。OCR 也可能有錯字、標點及排版差異。目前適合水平文字，旋轉或直排文字尚未完成辨識品質驗證。

## 安裝與離線使用

```sh
uv sync
uv run repdf
```

不需要安裝 Tesseract，也不需要另行下載模型。已安裝的 Tesseract 與舊模型不再使用。

`rapidocr==3.10.0` 的 Python wheel 內附 `PP-OCRv6_rec_small.onnx`，辨識模型約 20.3 MiB，包含中英文辨識字典；區域 OCR 另使用內附的 `PP-OCRv6_det_small.onnx`，約 9.5 MiB。使用明確本機模型路徑並檢查 SHA256，不使用預設模型自動下載流程。執行時不連線傳送 PDF。

辨識模型 SHA256：`6f327246b50388f3c176ae304bd95767ea6dc0c9ae92153ef8cbe210b3c14884`。

偵測模型 SHA256：`090f04abcd9d9a7498bc4ebf677e4cb9bdce1fe4197ddb7e529f1ef44e1ff94f`。

## 打包

`packaging/repdf.spec` 收集 RapidOCR 的設定、辨識／偵測模型與 ONNX Runtime 原生函式庫；不攜帶未使用的方向分類模型。

Windows EXE 與 macOS App／DMG 需分別在對應平台建置。封裝自我檢查加入實際 OCR 推論，避免僅確認 import 成功。

發布新版本時由 GitHub Actions 在雲端執行建置與封裝自我檢查；一般開發只從原始碼執行與測試。

## 驗證

```sh
uv run python -m pytest
```

測試包含正常文字不觸發、損壞字元觸發、拖曳高亮不觸發、空白選取不觸發、失敗保留原文、背景訊息協定、本機模型離線推論、純圖片區域辨識、反向框選、模式切換、全螢幕與背景程序到剪貼簿整合。合成測試 PDF 在執行時產生，不將使用者的 PDF 加入儲存庫。
